# Reflections and Conclusion

## Lessons learned

The project strengthened the team’s understanding of the SDLC, collaboration and systematic problem solving. The team learned that requirements must remain consistent across design, implementation and testing. Route matching and urgent alerts also demonstrated the importance of clear validation, understandable interfaces and reliable persistent data.

Trello supported planning, GitHub preserved version history, Figma and Draw.io captured design decisions, and iterative tests connected user workflows back to the requirements.

## Conclusion

The Campus Lost & Found prototype demonstrates found-item reporting and handover, timed route matching, public notices, urgent requests and nearby-volunteer alerts for Taylor’s University Lakeside Campus. It provides a practical foundation for structuring lost-and-found information.

The current system remains a prototype. Future development could add university-account integration, production deployment, broader device testing, accessibility review and operational governance.
